# Slidev・Marp・hono-decks との比較

[English](comparison.md)

デッキを hinote、[Slidev](https://sli.dev)、[Marp CLI](https://github.com/marp-team/marp-cli)、[hono-decks](https://github.com/ts-76/hono-decks) で作り、インストール、起動、書き出しを測りました。どのデッキも約20枚で、箇条書き、コード、表、引用を混ぜています。内容はツールごとに違います。さらに、Slidev・Marp・hono-decks のデッキには、それぞれが得意なことを1つずつ入れました。hinote のデッキには、その3つを hinote で再現したスライドを入れています（22枚）。元のファイルは [`bench/`](../bench) にあります。

hono-decks は、hinote と目的が少し違います。既存の Hono アプリ（Cloudflare Workers や Vite）に、MDX で書いた複数のデッキを組み込むためのものです。どちらも Hono の上でスライドを配信し、発表者画面や同期といった似た機能を持つので、並べています。

## 結果

2026-11-18 に測りました。hinote は、Bun で動かした場合と Node で動かした場合の両方を載せています。Node では esbuild と `@hono/node-server` を足しています。hinote の数字には、数式のために足した KaTeX も入っています。

- 環境は Apple M4 Pro、メモリ 48 GB、macOS 27.2.1、Bun 1.4.4、Node.js 26.13.1 です。
- 開発サーバーの2行と書き出しの時間は、何回か測った中央値です。開発サーバーは、初回を除いた3回を測りました。書き出しは、1回準備のために動かしたあとの5回を測りました。
- 初回の起動も、ほぼ同じでした（hinote は Bun で 0.15 秒、Node で 0.22 秒、hono-decks 0.38 秒、Slidev 1.72 秒、Marp 0.79 秒）。Slidev の初回は、Vite のキャッシュを消してから測っています。
- hinote の書き出しの2ファイルは、HTML と背景に使った画像です。Marp は画像をコピーしないので、1ファイルに画像は入っていません（画像は別に置く必要があります）。Slidev のファイル数が多いのは、数式のフォントなどが入るためです。

## hinote でどこまで再現できるか

ほかのツールの得意なことを、hinote で同じ見た目に作りました。どれもブラウザで表示を確かめています。

| ツール     | 得意なこと             | そのツールでの書き方              | hinote での作り方                                                                               | 追加したもの |
| ---------- | ---------------------- | --------------------------------- | ----------------------------------------------------------------------------------------------- | ------------ |
| Slidev     | LaTeX の数式           | `$$ ... $$`                       | KaTeX で MathML にして、描画するときに埋め込む小さなコンポーネント（`<Math tex="..." />`、9行） | `katex`      |
| Marp       | 背景画像を左右に分ける | `![bg left:40%](./photo.svg)`     | そのスライドの `css` で2列のグリッドにし、左の列を背景画像にする                                | なし         |
| hono-decks | 2段組のレイアウト      | `layout: two-cols` と `::right::` | `Row` の中に `Column` を2つ置く                                                                 | なし         |

- 書き方の手軽さでは、Markdown の一行で済むほかのツールに分があります。hinote はコンポーネントや CSS を書く分だけ長くなりますが、仕組みを自分で持てるので、細かく変えられます。
- hono-decks の island（ブラウザで動く部品）も試しましたが、私の構成ではブラウザ側で動き出すところまで確かめられなかったので、比較には入れていません。hinote では `<Script>` で同じことができます（サンプルのライフゲームとグラフの切り替えを参照）。

## 測り方

```bash
bun bench/run.ts            # インストール、書き出し、開発サーバーの応答まで
bun bench/run.ts --browser  # ブラウザに表示されるまでも測る（agent-browser が必要）
```

- **パッケージ管理:** どれも Bun でインストールしました。hinote の2つは、CLI を `bun` と `node` で起動し分けています。
- **インストール:** キャッシュを空にして測ったので、ダウンロードの時間を含みます。ネットワーク次第で変わるので、目安として見てください。
- **ブラウザに表示されるまで:** 開発サーバーを起動してから、headless Chrome にタイトルの文字が出るまでの時間です。ブラウザを操作する分の時間（0.1 秒ほど）も入っています。
- **書き出し:** `hinote build`、`hono-decks compile`、`slidev build`、`marp slides.md -o dist/index.html` です。
- **hono-decks の測り方:** `hono-decks init` で作った構成に、デッキを組み込んだ Hono アプリを足しました。普段の開発では Wrangler や Vite が起動時に `compile` を実行するので、「開発サーバー」は `compile` してから Bun でアプリを起動するまでを測っています。表示を待ったのは、スライドだけを出す `/decks/talk/presentation` です。

## 数字を読むときの注意

書き出したものは、中身がそろっていません。

- **hinote:** 視聴画面だけの HTML です。発表者画面と同期は入りません。
- **hono-decks:** `compile` が作るのは Hono アプリに組み込む TypeScript のモジュールで、単体で配るものではありません。そのため大きさは載せていません。配信に使うホスト（Wrangler や Vite）も、上のパッケージ数と大きさには入っていません。
- **Slidev:** Vue で動く静的サイト（SPA）で、発表者画面などの機能も入ります。
- **Marp:** 1ファイルの HTML で、発表者画面も入ります。

軽さは、機能を絞った結果でもあります。上の数字は、そのつもりで見てください。

## 機能の違い

|                      | hinote                                                                                     | hono-decks                                                               | Slidev                                                             | Marp CLI                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------ | ------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 書き方               | TSX（Hono/JSX）                                                                            | MDX（Markdown と Hono/JSX のコンポーネント）                             | Markdown と Vue コンポーネント                                     | Markdown と CSS テーマ                                                   |
| 動かす環境           | Bun か Node（Node では esbuild と @hono/node-server を追加）。デッキは Workers でも動く    | 既存の Hono アプリ（Cloudflare Workers、Vite、HonoX、Void）              | Node.js 22.22 以上                                                 | Node.js 18 以上                                                          |
| 部品を作る           | JSX のコンポーネント。async にもできる                                                     | MDX のコンポーネントと、ブラウザで動く island                            | Vue コンポーネント                                                 | なし（CSS で見た目を変える）                                             |
| 発表者画面           | 明示的に有効にしたときだけ（`hinote dev` は localhost で自動で有効）                       | あり。Durable Object を使って、別の端末からリモートで操作もできる        | あり。スマートフォンから操作もできる                               | 書き出した HTML にもある                                                 |
| 書き出し             | 視聴画面だけの HTML 1ファイル、または静的サイト（`prerender`）。PDF はブラウザの印刷で作る | 印刷用のページ。PDF・PNG は Cloudflare Browser Rendering で書き出す      | 静的サイト。PDF・PNG・PPTX には `playwright-chromium` を別に入れる | HTML 1ファイル。PDF・PPTX・画像には Chrome・Edge・Firefox のどれかが要る |
| サーバーとして動かす | デッキが Hono アプリなので、`app.route()` で自分のサーバーに組み込める                     | アプリに `app.route(decks.mountPath, decks.router())` で組み込むのが前提 | 開発サーバー                                                       | `-s` でディレクトリを配信する                                            |

Slidev は、hinote にない機能をたくさん持っています。描き込み、録画、LaTeX、Mermaid の図、アイコン、テーマの共有、エディタとの連携などです。Marp は、Markdown だけで書けて、PowerPoint にも書き出せます。hono-decks は、1つの Hono アプリで複数のデッキを配信する用途に向いていて、Workers の機能を使った書き出し、リモート操作、OGP 画像、埋め込み、レイアウトの種類などを持っています。

hinote が向いているのは、次のような場合です。

- 依存を小さく保ちたい。
- 書き出したファイルを軽くしたい。
- スライドを TypeScript のコードとして書き、データを読んで描画したい。
- 1つのデッキを CLI だけで作って発表し、必要なら Hono アプリとして別のアプリに組み込みたい。
